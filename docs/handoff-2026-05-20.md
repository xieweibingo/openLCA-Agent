### DQI 评分规则

- **地理代表性（35%）**：完全匹配=100，GLO=50，RoW=40，未知=20
- **技术代表性（35%）**：基于 fuzzy 名称相似度 ×100，类别匹配 +10
- **时间代表性（15%）**：固定 50（openLCA 过程无日期元数据）+ flag
- **元数据完整性（15%）**：name/id/category/location 各 25 分
- **置信度带**：overall ≥ 80 → high，≥ 50 → medium，< 50 → low

## 今日经验

1. **避免循环导入的结构模式** — DqiScore 模型放在 models.py 中，dqi.py 只放计算函数，双方都从 models 导入模型类，无需跨模块导入对方。
2. **gstack /qa 对 Python 项目的局限** — Web 浏览器测试不适用；手动跑 pytest + ruff 是有效替代方案。
3. **相似度引擎差异** — rapidfuzz 和 difflib.SequenceMatcher 对同一文本对返回不同分数。测试断言应避免写死特定分数阈值，用范围判断更稳。
4. **Windows GBK 编码问题** — Python 读文件默认用系统编码（GBK），显式指定 `encoding="utf-8"` 是必要的好习惯。
5. **PowerShell here-string 防 commit message 参数分裂** — 多行提交消息用 `@'...'@` 单引号 here-string，避免 `$` 和逗号被 PowerShell 解释。
